# Changelog

Заметные изменения Conductor. Формат свободный, даты — ISO.

## Unreleased — 2026-08-23

Внедрены правила из `docs/PARALLEL-WORK.md` и `docs/PROOF-LOOP.md` (перенос проверенной
практики из стороннего проекта-примера, к Conductor отношения не имеющего).
Документы остаются в `docs/` как исследовательская база — в runtime не копируются;
дублирующееся с существующими правилами (счётчики раундов, пропорциональность=тиры,
инверсия, «отчёт — не доказательство») осознанно НЕ переносилось.

- `orchestration.md`: блок PARALLEL MUTATION — гейты целого дерева изымаются из
  параллельных заданий и снимаются контролёром один раз после сериализации; запуск
  второго мутатора дописывает границы первому; до чтения отчёта — сверка изменённых
  файлов с объявленной областью (пустая разница); запрет проектных переформатирований;
  длинная задача первой. Слот 5 и Routing требуют карту покрытия
  (требование задания → место в артефакте или MISSING).
- `skeptic.md`: вердикт действителен только на неподвижном дереве; сверка карты
  покрытия с заданием — до содержательной проверки.
- `implementing.md`: remove-only-доказательство нового стража (T2+) — защита удалена →
  красный, возвращена → зелёный, оба вывода в отчёте; проверки поведения отделены от
  сторожей целостности (сторожа гоняются всегда); полнота сверяется с заданием,
  не с артефактом.
- `debugging.md`: падение, впервые замеченное после правки, сначала воспроизводится на
  до-правочном состоянии; красное там — существовавший долг отдельным пунктом.
- `subagent-contract.md`: карта покрытия в отчёте (п. 9); внешние ресурсы в уникальном
  пространстве имён, уборка с доказанными нулями, чужое не трогается (п. 11).
- Бюджеты: контракт 2500→3000 (SOFT_CAP хука синхронизирован), `implementing.md` и
  `orchestration.md` 6000→6500; HANDOFF обновлён.
- Отложено осознанно: реестр долгов с номерами/сроками (ни один гейт его не читает —
  вышла бы мёртвая проводка), правки `core.md` (места нет, предлагаемое уже есть в иной
  форме), цифры стоимости и лимиты по памяти (§9/§11 источников — специфика окружения
  проекта-примера, не Conductor).
- 2026-08-24, дополнение по проверке полноты (вопрос «полноценно сделал?» вскрыл два
  молча выпавших пункта): `methods.md` — CRITERIA FIRST для документных задач требует
  план обязательных пунктов ДО текста, карта покрытия сверяется с ним; `orchestration.md`
  — «не ставить рядом два тяжёлых приёма: приёмка контролёра не параллелится»
  (выпало при ужимании под бюджет). «Называть проверенные модули в отчёте» не добавлялось:
  покрыто правилом EVIDENCE контракта (команда+вывод в отчёте называют прогнанное).
- 2026-08-24, вторая волна: поимённые упоминания моделей убраны со всех живых
  поверхностей (CLAUDE.md, AGENTS.md, HANDOFF, комментарии `lint.sh`, фикстуры
  `settings-json-test.py`); исторические записи (спека, отчёты QA, прошлые записи этого
  файла) сохранены как архив. В `orchestration.md` добавлен блок MODEL AND EFFORT:
  effort — по тиру самой подзадачи, модель наследуется от сессии, легче — только для
  механической стадии с машинно-проверяемым выходом, верификатор не легче проверяемой
  работы; имена продуктов в правилах и промптах запрещены (поколения сменяются, правила
  остаются). Бюджет orchestration 6500→7000.
- 2026-08-24, манера ответа: в `deploy/global-CLAUDE.md` (и живую копию `~/.claude/CLAUDE.md`)
  добавлен §5.5 — ответ строится в порядке читателя (итог → что это значит → чем доказано
  → детали), а не в хронологии работы; первое лицо и активные глаголы вместо канцелярита;
  у каждого абстрактного утверждения — конкретный якорь (до/после, вход→выход, число, имя
  файла); имя, родившееся по ходу работы, либо не попадает в ответ, либо представляется
  при первом употреблении; одна мысль — один абзац, связки прописаны. Перенос в
  `core-body.md` отложен и назван: дайджесты 11988/12000 при внешнем жёстком лимите
  Antigravity — нужна отдельная волна ужимки корпуса.
- 2026-08-24, комплект спутников: `install.sh` шагом [4/5] (новый корневой скрипт
  `install-companions.sh`) по умолчанию ставит три инструмента — superpowers (официальный
  маркетплейс плагинов, запасной — `obra/superpowers-marketplace`), rtk
  (`cargo install --git`, без cargo — громкий SKIP с подсказкой про готовый бинарник,
  проводка через `rtk init -g`) и graphify (`uv tool install graphifyy`, запасной — `pip`,
  затем `graphify install` регистрирует навык). Политика по superpowers перевёрнута:
  раньше установщик его отключал (`--keep-superpowers` сохранял плагин), теперь плагин
  ставится вместе с Conductor — владелец пользуется обоими: Conductor даёт дисциплину
  процесса, superpowers — навыки рабочих процессов. Флаги: `--skip-companions` (весь шаг;
  его передаёт песочница smoke-теста в CI), `--no-superpowers` (отказ только от плагина),
  `--keep-superpowers` принимается как устаревший no-op. Провал спутника громкий и
  установку Conductor не валит, повторный запуск печатает «OK already»; `uninstall.sh`
  спутников не удаляет — это пользовательские инструменты. Скептик-раунд по этой волне
  снял пять опровержений, все закрыты: плагин, отключённый прежним установщиком, теперь
  включается (`plugin enable` по точному id, а не по подстроке имени); запасной
  маркетплейс пробуется даже если `marketplace add` упал (обычно «уже добавлен»); страж
  песочницы сравнивает канонические пути с профилем ОС (`USERPROFILE`), а не строку
  `$HOME`; pip-путь без PATH честно пишет «OK installed, not on PATH» вместо
  самопротиворечивого FAIL; отсутствие `install-companions.sh` в чекауте даёт громкий
  WARNING вместо смерти установки (CI этот случай не видит — он идёт с
  `--skip-companions`). Доводка по совещательным находкам второго раунда: при двух копиях
  плагина предпочитается уже включённая (включать отключённого близнеца — двойная
  загрузка), id заякорен (`team-superpowers@x` не считается), неудачный `enable` падает
  в ветку свежей установки, install.sh переживает окружение без HOME (дефолт из
  USERPROFILE). Linux-песочница с подменённым HOME осознанно НЕ считается песочницей:
  там инструменты уважают HOME и запись остаётся внутри целевого дома.

## Unreleased — 2026-08-21

Усилен контур доверия, найденный обзором после v2.1.1.

- `settings-json.py` удаляет собственные hook-команды на leaf-уровне и сохраняет чужих
  соседей внутри общего entry; новый read-only `audit-hooks` проверяет точные события,
  matcher, команды и timeout. Doctor использует этот аудит вместо текстового `grep`.
- A/B runner исключает live user settings в обоих плечах и выдаёт каждому invocation
  отдельные workspace и namespace доказательств. Плечо Conductor получает свежие runtime и
  settings; атомарный JSON-manifest хранит commit, digest фактической копии и artifact identity.
- `journal-report.sh` разделяет готовность объёма и качества: `PIPED` не участвует в
  quality gate, обязательны относимые PASS и FAIL. Перед подсчётом проверяется полный
  семипольный контракт writer-а, отброшенные строки видны отдельно. Итог разрешает только
  контролируемый эксперимент, никогда не удаление правил.
- CI запускает реальные sandbox/self-test этих трёх путей на Windows и Ubuntu.

## v2.1.1 — 2026-08-15

Мелкая волна по второму внешнему ревью + повторный A/B-замер.

- **A/B-замер v2** (`qa/reports/ab-report-v2.md`): поставляемый английский корпус
  перемерен на текущем поколении (`claude-fable-5`), 27/27 дисциплинарных ловушек в обоих
  плечах при полном n=5; плечо Conductor добавило reproduce-first в 12/12 debug-повторов
  при +2 хода медианы. Инструмент воскрешён как `qa/bench/` — оба плеча на живой
  авторизации, кредо-проблема v1-прибора исключена конструктивно.
- **Дефект дистрибуции, найденный бенчем:** база модулей в `core.md` была захардкожена
  под машину автора — на любой другой плейбуки молча не грузились. Теперь плейсхолдер
  `__CONDUCTOR_DIR__`, рендер при установке, охрана в линте (плейсхолдер обязателен,
  буквальные пути Users — запрещены) и в doctor (нерендеренное ядро = FAIL).

- Инжект уроков: секция инбокса теперь стоит выше индекса — обрезка бюджета больше не
  съедает новейшие захваты (в кейсе «полный стор + полный инбокс» строк инбокса
  приходило ноль, выживал только индекс).
- `tools/migrate-lessons.sh` и `playbooks/distill.md` уважают `CLAUDE_CONFIG_DIR`,
  как остальные хуки и инструменты.
- Линт проверяет синхронность `DISTILL_THRESHOLD` в трёх файлах.
- CI-бейдж во всех трёх README; `-h`/`--help` у `tools/doctor.sh`; `install.sh` не
  печатает имя несуществующего бэкапа при первой установке; счётчик тестов
  `settings-json` исправлен на фактические 12.

## v2.1.0 — 2026-08-15

Язык и волна ремонта по внешнему ревью.

- **Язык переключается целиком.** Корпус правил переведён на английский (русский корпус
  утягивал видимые рассуждения в русский при любом выборе языка); язык ответов — одна
  подставляемая фраза «Answer in Russian»; рассуждения идут на выбранном языке. Выбор
  делается в меню терминала при каждом запуске установщиков (Enter = прежний выбор),
  хранится в `~/.claude/conductor/reply-language`, его применяют все три установщика.
  Запрет `--no-verify` убран из правил (решение автора: коммит не блокируется — дисциплина
  в доказательстве до коммита).
- **Память починена.** Индекс уроков пересобирается из стора (повторная дистилляция его
  больше не стирает); инжект берёт новейшие строки и режет блок целыми строками (байтовый
  `cut` ломал UTF-8); инбокс ротируется до чтения (гонка закрыта); строки без `|` не
  файлятся мусором; DISTILL DUE напоминается каждым сообщением.
- **Инструменты.** `tools/doctor.sh` — здоровье установки; `tools/journal-report.sh` —
  чтение журнала прогонов с вердиктом достаточности данных (≥200 строк / ≥3 репозитория /
  ≥21 день); sentinel в `settings-json.py` заякорен (semiconductor-* больше не матчится).
- **Тесты и CI.** `qa/settings-json-test.py` (12 тестов на самый опасный код),
  `qa/lint-selftest.sh` (13 негативных кейсов линта), GitHub Actions на ubuntu + windows.
- **Правила откалиброваны.** Пороги fan-out при исследовании: >20 файлов / >1500 строк
  (углы поиска — не триггер); немутирующим задачам дан вход в тиры; лок/генерат исключён
  из RE-TIER; ложный маркер озвучивается раз за сессию; CONTROL GROUP сужен до артефактов
  дисциплинарного слоя; cross-model верификатор — из `crossmodel.conf`, не из зашитого CLI.
- LICENSE (MIT), англоязычный `README.en.md`, документированы побочные эффекты установки.
