## 1. Что это за проект (в двух фразах)

Conductor — автономная система поведения для Opus 4.8 в Claude Code: классифицирует задачу,
выбирает уровень риска, при необходимости запускает субагентов и скептик-проверку, требует
доказательств перед словом «готово». Заменяет плагин superpowers. Ставилась под конкретного
пользователя (соло-разработчик, Windows, PowerShell + bash, ответы на русском простым языком).

Работает вживую (проверено наблюдением, не отчётом установщика):

- Пульс-хук (UserPromptSubmit) — виден в каждом сообщении текущей сессии.
- Поведение: классификация 100% (8/8), отказ от необратимого (s1h), оркестрация с
  перепроверкой, дисциплина под давлением, S5 3/3 после v1.3.1.

**Коммит-замок — ПОЧИНЕН (v1.4.1, 2026-07-09).** Причины были две, обе доказаны
инструментально (лог реального payload + дискриминирующие тесты с кодовой страницей 866):
1. Безголовый pwsh читал stdin хука и вывод git в DOS-кодировке — путь «Новая папка»
   превращался в мусор, `rev-parse` не находил репозиторий, fail-open молча пропускал.
   Фикс: явный UTF-8 в обе стороны в `pre-commit-gate.ps1` + сообщение в stderr, когда
   корень репозитория не разрешается (молчание и прятало баг).
2. Матчер PreToolUse покрывал только `Bash` — коммиты через инструмент PowerShell вообще
   не попадали в хук. Фикс: `Bash|PowerShell` (install.ps1 + settings.json).
Проверено: ритуал фальсификации pass/FAIL/pass; живой коммит без маркера ЗАПРЕЩЁН харнессом;
путь с маркером пропускает и съедает маркер. Прежняя H2 из этого раздела закрыта.

## 5. Остаточная проверка для новой сессии

Матчер хуков загружается при старте сессии, поэтому одно осталось непроверенным вживую:
**коммит без маркера через инструмент PowerShell** — в новой сессии он должен блокироваться
так же, как через Bash. Одна команда: `git commit --allow-empty -m test` инструментом
PowerShell без маркера → жди запрет. Если прошёл насквозь — матчер `Bash|PowerShell` не
покрывает имя инструмента, смотри лог-инструментирование в истории (v1.4.1).

## 6. Как вносить любые изменения (цикл — не нарушать)

1. Правишь ТОЛЬКО в `runtime/` (репозиторий — источник правды).
2. `pwsh -NoProfile -File qa\lint.ps1` → должно быть `lint: PASS` (бюджеты, мёртвые ссылки,
   заглушки; ядро ≤9500 экранированных символов — обрезка на 10000 = тихая смерть).
3. Прогон на живом Opus хотя бы один:
   `pwsh -NoProfile -File qa\run-benchmark.ps1 -Mode conductor -Scenario <имя> -Reps 1 -Model opus`
   (сценарии — в `qa\scenarios\scenarios.psd1`; прогоны требуют залогиненных QA-домов
   `qa\home-*` с `.credentials.json` — они gitignored, на новой машине создаются копированием
   логина; см. историю, коммит про creds staging).
4. Синхронизация: `Copy-Item runtime\* $env:USERPROFILE\.claude\conductor -Recurse -Force`.
5. Изменил регистрацию хуков — `pwsh -NoProfile -File install.ps1` (сам бэкапит и перезаписывает).
6. Коммит по-английски; коммит-замок РАБОТАЕТ и требует свежий маркер
   `.git/conductor-verified` ПОСЛЕ доказательного прогона: `New-Item -Force -ItemType File .git\conductor-verified`.

## 7. Перенос на другой ПК

Скопировать всю папку репозитория → запустить `install.ps1`. Секретов в репозитории нет
(логины в `qa\home-*` gitignored и не переносятся). Требования: Windows + Claude Code
(залогинен), PowerShell (pwsh или powershell), git. Для Mac/Linux установщик надо адаптировать.
