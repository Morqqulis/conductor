## Что это

Conductor — дисциплинарная система для AI-агентов: классификация задачи до работы,
доказательство до слова «готово» и до коммита, самообучение через общую память.
Покрывает четыре среды: Claude Code (ядро + хуки), Cursor, Antigravity, Codex
(текстовые дайджесты правил). Репозиторий — источник правды и одновременно дистрибутив.

## Текущее состояние

- **Одна глобальная установка.** `install.sh` по умолчанию доставляет Claude runtime и
  все глобальные адаптеры; `install-global.sh` — совместимая обёртка того же CLI.
  `bootstrap.sh` / `install.ps1` скачивают официальный архив по точному коммиту без clone.
  После проверки установленного содержимого сохраняется версия; смешанные частичные
  установки не получают ложную общую версию. Существующие ручные правки блокируют повтор;
  перед записью сохраняется снимок для восстановления. Все изменяющие команды получают
  один замок и обнаруживают прерванную запись. RTK скачивается без Cargo, Graphify —
  в отдельную версионную среду. Управляемые копии обновляются до stable; распознанные
  uv/Cargo переходят на отдельные копии. Ошибки companions дают частичный код 3, неподключённый PATH
  не выдаётся за готовность. Неизвестные файлы и поздние личные правки не затираются.
  Инструкции, выбор RU/EN/AZ, ограничение Cursor и подключение навыка Codex — в README.
- **Подбор уроков по задаче.** `runtime/memory/recall.py` ищет
  кандидатов во входящем и разобранном хранилище, агент проверяет контекст и применимость.
  Свежесть только разрешает равенство релевантности; отсутствие совпадений не заполняется
  посторонними уроками. Никакой новой базы, сетевого сервиса или миграции. Подробности:
  `runtime/memory/recall.md`. Правила обслуживания/разбора уроков не меняются.
  16 проверок поиска (Windows: 2 пропуска привилегированных ссылок; Linux: все),
  10 проверок доставки/обслуживания, установки RU/EN/AZ и контроль со снятыми защитами.
  Доказательства и ограничения: `qa/reports/lesson-recall-2026-09-26.log`.
  Исходная проверка поиска отделена от итоговой установки; её статус — в журнале пакета.
- **CLI-обновление.** Оба установщика регистрируют собственные файлы и доставляют
  `conductor` / Windows `conductor.cmd` в `~/.local/bin`. `status`, `update --check`,
  `update [--ref main|тег|полный_SHA]`, `rollback --backup <путь>` работают без checkout.
  Источник фиксирован: официальный GitHub, отдельная временная папка. Обновляются только
  зарегистрированные компоненты; язык сохранён, память и рабочий Git не заменяются.
  Ручная правка управляемого файла, чужой файл или изменённые регистрации хуков дают отказ.
  Снимки вне runtime, условный откат, проверка установленных команд до записи версии;
  автоматическая блокировка параллельных install/update/uninstall/rollback. RTK/Graphify
  проверяются отдельным этапом; проектные адаптеры и ручное применение Cursor отдельно.
  Установка без manifest при конфликте сохраняется и требует восстановления регистрации.
  Протокол доставки имеет версию;
  несовместимый исходник не применяется. Инструкции и ограничения есть в README RU/EN/AZ.
- **Graphify — навигация, не источник истины.** В конце связного пакета карта обновляется
  из корня репозитория командой `uv run --with graphifyy==0.9.67 python tools/graphify-update.py --root .`
  (uv и Python 3.10+; альтернатива — Python с тем же пакетом). Это обслуживание репозитория,
  отдельно от `conductor update` для установленных правил. Только код — полный локальный
  AST без модели; изменённые документы — `NEEDS_SEMANTIC`, exit `3` и путь к запросу,
  без записи опубликованных файлов карты. Агент с навыком Graphify читает запрошенные
  источники и прежний граф, согласует исходные ID, рёбра, гиперрёбра и причины удалений,
  повторяет команду с `--semantic FILE --review FILE`. Входы — вне анализируемого набора
  или под `graphify-out/.conductor/`; `--prompt-file FILE` с фактическим промптом включает
  кеш с привязкой к источникам и промпту. Полнота смысла требует оценки агента.
  Единая команда применяет обязательные защиты, готовит результат отдельно, проверяет
  стабильность исходников, блокирует параллельные запуски средствами ОС и откатывает сбой.
  После жёсткого прерывания следующий запуск восстанавливает незавершённую запись;
  поздние чужие правки при конфликте останавливают восстановление с сохранением данных.
  Прежняя карта сохраняется до успешной публикации; копии и промежуточные файлы —
  в `graphify-out/.conductor/`, не для Git. `graph.json` заменяется последним, общей
  атомарной замены и блокировки чтения нет. Принудительного обхода нет; штатные команды
  Graphify, записывающие карту, нельзя запускать одновременно. Команды и ограничения
  согласованы в README RU/EN/AZ; новая приёмка и прежнее ручное восстановление разделены выше.
- **Память проверок — явный необязательный инструмент.** `runtime/evidence/cli.py`
  сохраняет команду, код завершения, полный вывод и наблюдаемые входы; `check` не запускает
  команду. `MATCH` не означает новый PASS и не доказывает полноту зависимостей. Проекты,
  клоны и worktree разделены, журнал активности не переиспользуется как доказательство.
  Оба установщика доставляют CLI, включая глобальную установку без Claude Code.
  80 тестов на Windows/Linux, установка на трёх языках и отрицательный контроль выполнены.
  В малой агентной пробе ошибок принятия нет, но сокращения запусков не измерено:
  изменение отпечатка окружения потребовало повторной проверки. Подробности и ограничения
  находятся в трёх README и журнале приёмки, не в новых обязательных правилах.
- Установщик дополнительных инструментов отличает подтверждённое состояние superpowers
  от ошибки или непонятного списка. Один успешный снимок и точная привязка статуса к записи;
  неизвестность даёт явный FAIL, но не отменяет установку Conductor. 14 изолированных
  сценариев: `qa/companions-test.py`; первичные журналы: `qa/reports/companions-2026-09-25/`.
- **Хуки и установщики runtime — на Bash.** Отдельный PowerShell-скрипт
  `tools/schedule-memory-backup.ps1` восстанавливает расписание Windows только по явному запуску.
  `python3` нужен установщикам (правка JSON-конфигов других инструментов) и журналу
  прогонов тестов в рантайме — без python журнал молча не пишет ни строки (это его
  осознанный fail-open); остальные хуки — чистый bash.
- Пользовательские `graphify` / `@RTK.md` в глобальном `CLAUDE.md` сохраняются установкой.
  Состояние конкретной машины проверяется командой `bash tools/doctor.sh` — не по памяти
  этого файла: установка могла быть снесена после любой его правки.
- **Маркерный гейт снят окончательно** во всех репозиториях, где стоял; вычистка чужих
  машин — `tools/sweep-git-gate.sh` (см. `uninstall.sh --sweep-roots`).
- **Память перестроена:** накопленные уроки разложены по файлам с индексом
  (`tools/migrate-lessons.sh`); индекс пересобирается из стора при каждом прогоне.
  Установщик доставляет этот инструмент в `memory/`: обслуживание возможно без исходников.
  Новый стартовый блок передаёт адреса поиска по задаче, без выбора уроков по свежести.
  Неполные даты уходят в конец индекса, архивы двух разборов в одну секунду не перезаписываются.
  Восстановление полного приватного репозитория и расписания: `docs/memory-recovery.md`.
- **Отмена — только своих изменений.** Точные снимки до задачи учитывают dirty/untracked;
  перед отменой проверяется ожидаемое состояние. Проверка без исправления идёт в отдельной
  копии с сохранением текущего теста. Поздние чужие изменения не перезаписываются.
- **Контур доверия проверяется по структуре и поведению.** `settings-json.py` удаляет
  только собственные leaf-команды внутри общего hook-entry и сохраняет чужих соседей;
  `audit-hooks` проверяет точную форму регистрации, а doctor запускает smoke только после
  успешного аудита. CI гоняет отдельные sandbox/self-test для doctor, журнала и бенча.

## Архитектура

| Слой | Файлы | Кому |
|---|---|---|
| Ядро | `runtime/core.md` (sentinel CONDUCTOR-CORE-v1-7f3a) | Claude Code |
| Плейбуки | `runtime/playbooks/` (debugging, implementing, verification, investigating, orchestration, skeptic, distill, methods) | Claude Code |
| Контракт субагента | `runtime/subagent-contract.md` (правила исполнителя) | субагенты |
| Хуки | `runtime/hooks/*.sh` + общий `payload.sh`; отдельно `test-run-journal.sh` — пассивное наблюдение за прогонами тестов, ничего не блокирует | Claude Code |
| Дайджест | `adapters/core-body.md` — **единственный источник**; `tools/build-digests.sh` собирает из него файлы Cursor и Antigravity | Cursor, Antigravity, Codex |
| Память | `~/.claude/conductor/lessons.md` (входящее) + `lessons/` с `INDEX.md` (разобранное) | все |
| Доказательства проверок | `runtime/evidence/`; данные отдельно от уроков и Git, по проектам | все агенты с Python |

Установка: один `install.sh` по умолчанию ставит Claude Code, Cursor/AG/Codex и спутники.
`--scope claude|global|all` выбирает состав; `--language <имя>` пропускает меню языка.
`bootstrap.sh` / `install.ps1` скачивают `tools/bootstrap.py`, который загружает архив
конкретного коммита с официального GitHub во временную папку, без клонирования.
Загрузчик требует Python 3.10+, Git и Bash; Windows использует именно Git Bash, не WSL.
`install-global.sh` сохранён как совместимая обёртка; второй запуск не нужен.
`tools/install-preflight.py` теперь только проверяет подготовленный план, ничего не пишет.
Общий CLI сохраняет снимки в `~/.local/state/conductor/updates/`, использует их для
`rollback` и восстановления после сбоя; конкурирующий запуск получает явный отказ замка.
`install-project.sh
--repo <путь>` (проектные адаптеры; подставляет сохранённый язык, `--language` —
переопределение только для этого проекта, машинный выбор не трогает), `uninstall.sh`
(симметричное удаление, есть `--dry-run`). Выбор языка хранится в
`~/.claude/conductor/reply-language`; повторные запуски установщиков его не сбрасывают.
После проверки Conductor CLI запускает Superpowers через `install-companions.sh
--only-superpowers`, затем общий координатор RTK/Graphify. Подробности — в трёх README.
Политика по superpowers перевёрнута: раньше плагин отключался, `--keep-superpowers` —
теперь принимаемый no-op, отказ — `--no-superpowers`, весь шаг — `--skip-companions`
(его передаёт песочница CI). Провал спутника обозначается FAILED и кодом 3;
подтверждённый Conductor остаётся, `uninstall.sh` спутников не трогает.

## Ключевые решения волны v2.0

- **Правила приведены к документации Anthropic** по текущему поколению reasoning-моделей:
  - убрана избыточная верификация как инструкция (модели перепроверяют себя сами);
    скептик больше не обязателен на каждом T3 — он для работы, которую ты не видел;
  - роли разведены: ОРКЕСТРАТОР (главная сессия) делегирует крупное и независимое,
    не делегирует мелочь, не проверяет субагентом свою же работу; ИСПОЛНИТЕЛЬ (контракт
    субагента) не делегирует дальше, применяет инструкции ровно в заданной области,
    при поиске дефектов отдаёт всё найденное без самофильтрации;
  - добавлен раздел про длинные автономные прогоны: сверка заявлений с результатами

## Бенчмарк удалён (2026-07-28). Авторизации и ключей в проекте нет

**Conductor не требует авторизации.** Ключи нужны были только измерительному прибору, а не
системе: сломанная авторизация никогда не мешала Conductor работать. Прибор удалён целиком —
`qa/run-benchmark.sh`, сценарии, пять ловушек-фикстур, изолированные каталоги настроек и
стенограммы прогонов. Ключей в репозитории нет и не будет.

Что прибор успел доказать до удаления (единственный состоявшийся прогон, сценарий `verify`):

- **Плечо с Conductor доказано сквозным прогоном.** Сентинел `CONDUCTOR-CORE-v1-7f3a` в
  стенограмме дважды, ноль записей `hook_non_blocking_error`, и — главное — строка
  `Conductor: debug | T1 | core only` в ответе агента. Последнее важнее первого: сентинел
  показывает, что текст доставлен, а объявление типа и уровня — что правила **сработали**.
- **Контрольное плечо не измерялось.** Отказ аутентификации. Причина доказана контрольными
  суммами: прогон обновил OAuth-токен, обновление отзывает прежний, и вторая копия с тем же
  токеном стала недействительной. Два плеча не могут работать от одной скопированной пары
  ключей — кто первым обновит, тот отзовёт у остальных.

Почему прибор не чинили дальше, а убрали: `qa/reports/baseline.md:62-63` прямо говорит, что
эти ловушки не воспроизводят длинные сессии, ради которых правила и держат. Чинить прибор,
заведомо не покрывающий нужный класс, и платить за это выбитой рабочей сессией владельца при
каждом замере — не туда. Данные живой работы даёт журнал прогонов тестов, и он копит их сам.

**Что сохранено намеренно.** Отчёты `qa/reports/` — это измерения, а не прибор: на них
держится разбор правил по корзинам, и README с этим файлом ссылаются на их строки. Там же
лежит `qa/reports/baseline-values-file.md` — те самые 56 строк файла ценностей, с которыми
контрольная группа прошла 13 испытаний из 13; это вещественное доказательство к условию в
README, а не фикстура. Содержимое не менялось, только путь.

Возврат к разбору правил по корзинам — по данным журнала, как предписывает `baseline.md:65`.

## Деплой-цикл (незыблемо)

Правки ТОЛЬКО в `runtime/` и `adapters/core-body.md` → `bash tools/build-digests.sh` →
`bash qa/lint.sh` (он же печатает занятость бюджетов) → установщики → проверка живых
копий grep'ом, не верой.

Бюджеты: payload ядра ≤9500 экранированных символов (харнесс молча режет на 10000 —
**замерь ДО правки ядра**), контракт ≤3000 (в паре с SOFT_CAP хука subagent-start.sh),
плейбуки ≤6000 (implementing ≤6500, orchestration ≤7000, verification ≤5000), probes ≤3600,
дайджесты ≤12000 (Antigravity молча обрезает).
