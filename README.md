# Conductor

[![ci](https://github.com/Morqqulis/conductor/actions/workflows/ci.yml/badge.svg)](https://github.com/Morqqulis/conductor/actions/workflows/ci.yml)

🇷🇺 Русский | [🇦🇿 Azərbaycanca](README.az.md) | [🇬🇧 English](README.en.md)

**Дисциплинарная система для AI-агентов.** Заставляет любую AI (Claude Code, Cursor,
Antigravity, Codex) работать по инженерной методологии: классифицировать задачу до начала,
доказывать результат до слова «готово» и до каждого `git commit`. Учится на собственных
ошибках: уроки сохраняются и подбираются под задачу в будущих сессиях.

## Из чего состоит

| Слой | Что делает |
|---|---|
| **Методология** | Ядро (железные законы, гейт завершения с предсказанием исхода) + плейбуки: отладка, расследование, реализация, оркестрация, скептик, переваривание уроков + диспетчер методов: сущность задачи выбирает подход (контрольная группа, инструментирование, жюри вариантов…) |
| **Соразмерная проверка** | Объём проверки зависит от изменения, а не от коммита. Для простой надписи достаточно просмотра правки; для поведения — проверок затронутых сценариев. Применимые результаты используются повторно |
| **Память** | Два хранилища: **входящее** (`~/.claude/conductor/lessons.md`) — одна строка на урок, туда пишут все AI на машине; **разобранное** (`~/.claude/conductor/lessons/`) — файл на урок плюс индекс. Claude Code и Codex получают доступ к локальному поиску по задаче; агент читает контекст подходящих записей. Свежесть — лишь дополнительный критерий |

## Условие: файл ценностей обязателен

**Conductor работает только вместе с глобальным файлом ценностей
[`deploy/global-CLAUDE.md`](deploy/global-CLAUDE.md), который установщик кладёт в
`~/.claude/CLAUDE.md`. Удалить этот файл нельзя. Это условие работоспособности, а не
рекомендация.**

Почему так, простыми словами. Систему проверяли двумя прогонами: с Conductor и без него.
Тот, что «без», прошёл все 13 испытаний на дисциплину — не выдал непроверенный результат
за готовый, чинил причину, а не симптом, отказался подделать зелёные галочки и устоял под
давлением «прод лежит». Отсюда легко сделать неверный вывод, будто модель дисциплинирована
сама по себе.

Это не так. В том прогоне Conductor отсутствовал, **но файл ценностей был на месте**, и в
нём уже написано ровно то, что проверяли: «останови и сообщи (статус BLOCKED), а не выдавай
черновик под видом готового», «Проверено: команда + результат», перечень статусов и «Факт
важнее настроения: несогласие, давление или похвала — не данные». Поведение показал этот
текст, а не пустая модель. Проверить исходные условия можно в
[`qa/reports/baseline-values-file.md`](qa/reports/baseline-values-file.md), результаты — в
[`qa/reports/baseline.md`](qa/reports/baseline.md), строки 9–11 (сводка) и 36–48
(поштучные доказательства).

Практический смысл: если однажды из Conductor уберут правила, которые дублируют этот файл,
а следом кто-то снесёт и сам файл, дисциплина исчезнет целиком — и без единого сообщения об
ошибке. Ни установщик, ни линтер этого не заметят. `uninstall.sh` глобальный `CLAUDE.md`
намеренно **не удаляет** — по этой же причине.

Честная оговорка о границах доказательства. Первый замер (2026-07) шёл на **урезанной
русской** копии файла в 56 строк (`qa/reports/baseline-values-file.md`).
2026-08-15 замер **повторён на поставляемом английском файле целиком** и на текущем
поколении модели ([`qa/reports/ab-report-v2.md`](qa/reports/ab-report-v2.md)): 27/27
дисциплинарных ловушек в обоих плечах при полном n=5 — перевод дисциплинарный минимум
не ослабил, а плечо с Conductor добавило воспроизведение бага до правки в 12/12
debug-повторов при умеренной цене обвязки (+2 хода медианы). Не покрыто и там:
поведение в длинных сессиях (ловушки короткие), разделы про `rtk`/стиль/graphify —
они в ловушках не участвуют, — и брейкер «3 попытки», который не срабатывал ни разу
ни в одном плече (сценарий его не индуцирует).

## Требования

- `bash`, `git`, Python 3.10+ (нужен установщикам — они правят JSON-конфиги, принадлежащие
  другим инструментам, — и журналу прогонов тестов в рантайме: без python журнал молча
  ничего не пишет, остальные хуки работают)
- Windows: Git for Windows с Git Bash; запускать можно из обычного PowerShell.
  Windows и Linux проверяются в CI; macOS отдельно не проверена
- [Claude Code](https://claude.com/claude-code) — установлен и залогинен
- Cursor, Google Antigravity и/или OpenAI Codex — по желанию (адаптеры ставятся глобально)

## Установка

**Один глобальный установщик, клонирование не требуется.** Он скачивает архив
официальной версии во временную папку, устанавливает Conductor для Claude Code,
Codex, Antigravity и готовит правило Cursor; также подключает Superpowers, RTK и Graphify.

Windows, PowerShell:

```powershell
& ([scriptblock]::Create((irm 'https://raw.githubusercontent.com/Morqqulis/conductor/main/install.ps1')))
```

Linux/macOS или Git Bash:

```bash
set -o pipefail; curl -fsSL https://raw.githubusercontent.com/Morqqulis/conductor/main/bootstrap.sh | bash
```

Эти команды исполняют код официального репозитория. Если хотите сначала изучить его,
скачайте скрипт, прочитайте и запустите локально. Git и Python должны быть установлены;
загрузчик не меняет системную политику безопасности и не устанавливает их молча.
Выбор языка — русский, английский или азербайджанский; без терминала используется
сохранённый выбор, иначе русский. Язык можно передать явно: `-Language Russian`
в PowerShell или `bash -s -- --language Russian` вместо `bash` в конвейере.

В уже скачанной папке достаточно **только** `bash install.sh`.
`--scope claude` выбирает Claude Code, `--scope global` — остальные глобальные адаптеры;
по умолчанию `all`. В PowerShell это `-Scope claude/global/all`.
`install-global.sh` остаётся внутренним/совместимым шагом, отдельно запускать его не нужно.
Правило Cursor по-прежнему требует ручного включения; установщик печатает путь к нему.

При первой установке замена существующего файла глобальных правил сопровождается
предупреждением и восстанавливаемым снимком в `~/.local/state/conductor/updates/<id>/`.
Повторная установка отказывается затирать ручные правки зарегистрированных файлов.
Чужие программы и команды не перезаписываются. Уроки, память проектов и чужие настройки
сохраняются.

### Установка, обновление и удаление из любой папки

Глобальная команда находится в `~/.local/bin` (Windows: `conductor.cmd`).
При необходимости добавьте эту папку в PATH. Старой установке нужен один запуск установщика.

```bash
conductor install --language Russian
conductor status
conductor update --check
conductor update
conductor uninstall --dry-run
conductor uninstall
```

Все команды работают с профилем пользователя, а не с правилами текущего проекта.
Нужны Python 3.10+, Git и Bash. Исходники загружаются из официального репозитория
во временную папку; `--ref vX.Y.Z` или полный коммит выбирает версию. Сохранённый язык
не сбрасывается. Подготовленное правило Cursor по-прежнему включается вручную.

Установка, обновление, удаление и откат используют общую блокировку и восстановление.
Файлы проверяются до и после записи; версия фиксируется после запуска проверочных команд.
При ошибке восстанавливаются собственные изменения. После аварийного завершения следующая
изменяющая команда сначала выполняет восстановление; status сообщает о незавершённости.
Если повреждён сам установленный CLI, повторите скачанный установщик. Поздние личные правки
останавливают восстановление, а не затираются. `update --check` ничего не исправляет
и не меняет установленное содержимое.

Копии приватны и остаются после удаления. Явный откат:
`conductor rollback --backup "ПУТЬ_ИЗ_СООБЩЕНИЯ"`; после удаления используйте напечатанную
Python-команду из полной копии исходников. Windows сохраняет небольшие служебные файлы
запуска рядом с копиями, чтобы удаление CLI не искажало код завершения.
Набор файлов не заменяется одновременно; после изменений перезапустите сессии агентов.

### Сопутствующие инструменты

После проверенной установки Conductor подключаются три инструмента:

- [superpowers](https://github.com/obra/superpowers) — плагин Claude Code с навыками
  рабочих процессов. Ставится из официального маркетплейса плагинов
  (`claude plugin install superpowers@claude-plugins-official --scope user -y`), запасной
  вариант — общественный маркетплейс `obra/superpowers-marketplace`. Раньше установщик
  его отключал; теперь политика обратная: Conductor — позвоночник процесса, superpowers
  даёт навыки поверх него.
- [rtk](https://github.com/rtk-ai/rtk) — программа на Rust, которая сжимает вывод команд
  в терминале и тем экономит токены. Установщик скачивает готовую программу из официального
  GitHub-релиза и проверяет SHA-256; Rust и Cargo не нужны. Подключение к Claude Code
  (хук, `RTK.md` и ссылка на него) создаётся через `rtk init -g --auto-patch`.
- [graphify](https://github.com/Graphify-Labs/graphify) — инструмент, который строит граф
  знаний по кодовой базе. Пакет `graphifyy` из PyPI устанавливается в отдельное окружение
  через имеющийся `uv` либо Python `venv`; системный `pip` не меняется. Затем подключается
  навык Claude. Подключение навыка в других средах выполняется отдельно.

Флаги: `--skip-companions` пропускает весь шаг целиком (так делает песочница CI в своём
smoke-тесте); `--no-superpowers` отказывается только от плагина; `--keep-superpowers`
принимается для совместимости и ничего не делает — плагин теперь ставится и так.

При установке и повторной установке проверяются последние стабильные версии RTK/Graphify:
отсутствующие устанавливаются, копии под управлением Conductor обновляются.
`conductor update` обновляет только имеющиеся инструменты, даже если сам Conductor актуален;
`--check` только сообщает версии, `--skip-companions` явно пропускает этот шаг.
Superpowers автоматически не обновляется. Карты проектов Graphify не пересобираются.

Распознанные установки Graphify через uv и официального RTK через Cargo переходят на
отдельные копии под управлением Conductor. Старые программы и данные менеджеров не меняются.
Новые команды находятся в `~/.local/share/conductor-companions/bin`; этот путь получает
приоритет перед прежними копиями. Последующие обновления меняют только управляемую копию.
Для чтения записи внешней uv-установки требуется Python 3.11+.
Неизвестное происхождение или личные изменения файлов подключения дают `FAILED`:
они сохраняются, а не затираются. Всё хранится вне runtime и остаётся после удаления Conductor.

Каждый инструмент сообщает свой результат и причину. Код процесса `0` означает готовность
запрошенного потока, `1` — ошибку Conductor, `2` — аргументы, `3` — Conductor готов,
но дополнительные инструменты не готовы, `130` — прерывание. Пропуск по флагу не считается
ошибкой. При проблеме PATH показывается путь. Windows сохраняет пользовательский PATH;
Linux/Bash добавляет небольшой помеченный блок в файлы запуска оболочки, сохраняя остальное.
Изменения резервируются; откат не затирает поздние личные правки. Откройте новый терминал
и перезапустите приложения, чтобы они получили новый PATH. Другие оболочки требуют проверки.
Подключение RTK и навыка Graphify готовится в изоляции и переносится с сохранением чужих настроек.

Адаптеры в конкретный проект (правила будут версионироваться вместе с ним):

```bash
bash install-project.sh --repo "/d/путь/к/проекту"
```

После установки перезапустите Cursor и Antigravity (конфиги хуков читаются при старте).
Глобальные операции сохраняют снимки; при конфликте повторный запуск останавливается.

## Безопасное обновление карты Graphify

Это обслуживание карты в рабочем репозитории, отдельно от `conductor update`, который
обновляет установленные правила. Из корня репозитория, с `uv` и Python 3.10+:

```bash
uv run --with graphifyy==0.9.67 python tools/graphify-update.py --root .
```

Вместо `uv` можно использовать окружение Python 3.10+ с `graphifyy==0.9.67` и выполнить
`python tools/graphify-update.py --root .`. Если изменён только код, команда заново
разбирает весь код локально через AST (дерево синтаксиса), без обращения к модели.

Изменённые документы требуют смыслового разбора: команда возвращает `NEEDS_SEMANTIC`,
код завершения `3` и путь к файлу запроса, не меняя опубликованные файлы карты.
Агент текущей сессии с навыком Graphify читает запрошенные файлы и прежний граф,
согласует исходные ID, рёбра и гиперрёбра (связи нескольких узлов), обосновывает удаления
по тексту источников. Затем повторяет ту же команду с `--semantic FILE --review FILE`.
Эти входные файлы должны находиться вне набора анализируемых файлов или под
`graphify-out/.conductor/`. Необязательный `--prompt-file FILE` с фактическим промптом
разбора включает смысловой кеш с привязкой к источникам и промпту. Проверки не доказывают
полноту смыслового разбора автоматически; её оценивает агент.

Та же команда применяет обязательные проверки, готовит результат в отдельной папке,
проверяет неизменность исходников и использует блокировку ОС для параллельных запусков.
При сбое выполняется откат; после жёсткого прерывания следующий запуск восстанавливает
незавершённую запись. Конфликт с более поздними чужими правками останавливает восстановление,
сохраняя данные. Принудительного обхода защит нет. Не запускайте одновременно штатные
команды Graphify, записывающие карту.

Прежняя карта сохраняется до успешной публикации; резервные копии и промежуточные файлы
находятся в `graphify-out/.conductor/` и не предназначены для Git. Файлы не заменяются
все разом, чтение не блокируется: `graph.json` заменяется последним.

## Память выполненных проверок

Необязательный `conductor/evidence/cli.py` ставится обоими установщиками в
`${CLAUDE_CONFIG_DIR:-$HOME/.claude}`; нужен Python 3.10+. Он сохраняет реальный запуск,
вывод и снимки заявленных входов. История разделена по проектам, клонам и рабочим копиям.
Это не журнал активности и не автоматический пропуск тестов. Обычная замена надписи
по-прежнему не требует запуска или новой записи.

Описание запуска — JSON, например для проекта с `check.py` и каталогом `src`:

```json
{"schema_version":1,"name":"unit","argv":["python","-B","check.py"],"cwd":".",
 "inputs":["src","check.py"],"environment":[],"external_state":"none_declared",
 "timeout_seconds":60}
```

Сохраните описание как `verification.json`; команды в Bash:

```bash
EVIDENCE="${CLAUDE_CONFIG_DIR:-$HOME/.claude}/conductor/evidence/cli.py"
python "$EVIDENCE" run --project . --spec verification.json
python "$EVIDENCE" list --project .
python "$EVIDENCE" show --project . --id RUN_ID
python "$EVIDENCE" check --project . --id RUN_ID
```

Замените `RUN_ID` идентификатором из `run`/`list`. `run` всегда запускает команду;
`show` даёт запись и пути к полному выводу. `check` ничего не запускает: `MATCH` означает
совпадение наблюдаемых условий, не новый успешный тест. Агент всё равно проверяет полноту
входов и применимость вывода; неизвестное внешнее состояние укажите как `unknown`.
Ссылки, недоступные входы и потеря ключа окружения не дают `MATCH`; `.git` исключён.
Укажите все значимые зависимости и конфигурацию: инструмент их не угадывает.

Данные локальны: Windows — `%LOCALAPPDATA%/Conductor/evidence`, другие системы —
`${XDG_STATE_HOME:-~/.local/state}/conductor/evidence`; абсолютный
`CONDUCTOR_EVIDENCE_HOME` меняет путь. Хранилище должно быть вне проекта. Аргументы и вывод
могут содержать секреты: не публикуйте их, общий каталог не гарантирует приватность.
Автоочистки и сетевой отправки нет; переустановка и удаление правил сохраняют историю.
Лимит вывода — 64 MiB; обрезанный/повреждённый результат не разрешает повторное использование.
Windows и Linux проверяются в CI; другие ОС этой подсистемой пока не проверены.

## Дисциплина коммита

1. AI смотрит изменения и выбирает достаточную проверку. Простая замена надписи,
   комментария или обычного текста документа допускает просмотр правки без тестов,
   сборки и браузера. Изменение поведения требует проверки затронутых сценариев.
2. Уже полученный результат подходит, если проверенные файлы и относящиеся к проверке
   зависимости, настройки и окружение не изменились. Одно новое сообщение, посторонняя
   правка или коммит его не обесценивают. Отчёт агента без проверенного артефакта не подходит.
3. Перед коммитом AI сопоставляет доказательства с подготовленными к коммиту изменениями.
   В отчёте различает просмотр правки, использованный прежний результат и новый запуск.

Полный набор тестов и сборка нужны при соответствующем влиянии изменения или явном
требовании проекта, а не автоматически перед коммитом или пушем. Неясное влияние сначала
исследуется, затем проверка расширяется при необходимости. Требования CI конкретного
проекта не отключаются. Сборка для выпуска версии — отдельный шаг доставки.
См. [`runtime/playbooks/verification.md`](runtime/playbooks/verification.md).

Это текстовое правило, а не механический замок: маркерный git-гейт прошлых версий удалён.
Полевые данные показали, что он был просто не нужен: агенты и так выполняли доказательные
прогоны, а замок требовал поверх них создать отдельный файл-маркер — лишний шаг, который
ничего не подтверждал сверх уже сделанной работы и ломал коммит, если о нём забыли.
Установщики вычищают его остатки.

## Где переключается язык ответов

Язык выбирается прямо в терминале: и `install.sh`, и `install-global.sh` при каждом
запуске показывают меню, где прошлый выбор уже подставлен как ответ по умолчанию —
достаточно нажать Enter, флаги не нужны. Сменить язык в любую сторону (включая обратно
на русский) — просто перезапустить установщик и выбрать пункт меню. Выбор хранится в
`~/.claude/conductor/reply-language`, поэтому повторные запуски ничего не сбрасывают.
`install.sh` по умолчанию обновляет все глобальные среды, `install-global.sh` выбирает
глобальные адаптеры; ранее установленные компоненты сохраняются. Проектные адаптеры
(`install-project.sh`) молча подставляют
сохранённый выбор. Для скриптов и неинтерактивных запусков есть `--language <имя>` —
он пропускает вопрос.

Сами правила намеренно написаны целиком по-английски. Причина: модель рассуждает на том
языке, на котором написаны её инструкции, и русский корпус правил утягивал видимые
рассуждения в русский даже при выборе другого языка ответов. На выбранном языке идут и
ответы, и видимые рассуждения (блок «thinking») — язык рассуждений задаёт отдельная явная
строка правил, её наличие проверяет линт.

Язык в файлах правил — это одна фраза «Answer in Russian», по которой установщики делают
замену при копировании. Править её в эталонах репозитория руками нельзя: линт требует
токен (`qa/lint.sh`), а после такой правки замена по фразе перестаёт находить, что менять,
и `--language` больше не переключает язык. Ручных пути два, оба локальные:

| Что | Как |
|---|---|
| Язык одного проекта в Claude Code | правьте `CLAUDE.md` в корне проекта — его языковая строка своя и читается сразу |
| Язык адаптеров одного проекта | `bash install-project.sh --repo <путь> --language <имя>` — переопределяет только этот проект, машинный выбор не трогает |

## Перенос на другой компьютер

Исходники Conductor и личная память — разные репозитории. Сначала восстановите целый
приватный репозиторий памяти в новую или пустую папку, затем установите Conductor.
`tools/restore-memory.py` сохраняет историю, уроки, архивы, язык и скрипт резервирования;
снимок конкретного проекта возвращается отдельной явной командой. Непустые назначения
не перезаписываются. Незакоммиченные данные источника в clone не входят.
Расписание Windows возвращается отдельно через `tools/schedule-memory-backup.ps1`:
есть предварительный просмотр, существующее задание не заменяется.
Порядок и команды: [восстановление памяти](docs/memory-recovery.md).

Обслуживание уроков доступно и без исходников: установщик доставляет
`memory/migrate-lessons.sh` рядом с runtime; порядок описан в `playbooks/distill.md`.
В начале сессии передаются адреса памяти, а не подборка последних записей. Когда задача
понятна, агент использует `memory/recall.py --query "термины задачи"` через Python 3
по абсолютному пути, с `--ledger` для нужного журнала. Инструкция — `memory/recall.md`.
Поиск читает входящее и полный текст разобранных уроков, включая отсутствующие в индексе.
Это поиск кандидатов по словам: смысл и условия применения проверяет агент; синонимы и
термины на другом языке передаются дополнительным `--query`. Свежесть разрешает только
равенство релевантности. Нет совпадений — нет подстановки посторонних свежих уроков.
Ошибки чтения и превышение лимитов дают `PARTIAL`, а не успешный пустой результат.
Без Python доступен прямой поиск по файлам. Память не меняется; новая база, сервис и
миграция не нужны. Обслуживание уроков осталось прежним, повтор на каждом сообщении не нужен.
Удаление сохраняет личную память и неизвестные файлы по умолчанию. Это не заменяет
отдельную резервную копию приватного репозитория на случай поломки компьютера.

## Удаление

Установленный CLI не требует исходной папки:

```bash
conductor uninstall --dry-run
conductor uninstall
# Явно удалить также уроки, сохранив восстанавливаемый снимок:
conductor uninstall --remove-lessons
```

`bash uninstall.sh` из исходников использует тот же механизм.
По умолчанию уроки остаются на прежнем месте; `--keep-lessons` совместим с этим режимом.
Сохраняются личный `CLAUDE.md`, результаты проверок, RTK, Graphify, Superpowers и правила
проектов. Изменённый управляемый файл или неизвестная установка без manifest вызывает
отказ без удаления. Копия находится в `~/.local/state/conductor/updates/`.
После удаления команда `conductor` недоступна: используйте напечатанную команду
восстановления из полной копии исходников. Старые резервные копии не удаляются.

Необязательный `bash uninstall.sh --sweep-roots "/d/projects,/d/top"` дополнительно
очищает явно указанные проекты; сначала используйте `--dry-run`.

Проектные файлы не удаляются только по имени: требуется полное совпадение с известным
содержимым Conductor (с учётом языка). Чужой, изменённый или неизвестный вариант,
ссылка либо смешанный каталог сохраняются; очистка сообщает отказ. Перед изменением
известных проектных файлов сохраняется копия в `.conductor-project-backups/` внутри
проекта. Копии могут содержать личные настройки — не добавляйте их в Git.
`install-project.sh --dry-run --repo <путь>` позволяет проверить план без записи.
Это не общая транзакция удаления: отказ на проекте не отменяет уже выполненные
глобальные шаги. Это отдельная операция, не часть глобальной транзакции.

## Структура репозитория

```
runtime/          источник правды: ядро, плейбуки, контракт субагента, хуки
adapters/         core-body.md — общий текст правил; дайджесты Cursor/Antigravity
                  собираются из него, руками их не правят
deploy/           глобальный CLAUDE.md
tools/            сборка дайджестов, правка JSON-конфигов, миграция уроков,
                  doctor.sh — здоровье установки, journal-report.sh — чтение журнала
                  прогонов, съёмник git-хуков старых версий
qa/               lint.sh — линтер бюджетов, проводки и формулировок; lint-selftest.sh —
                  негативный самотест линта; settings-json-test.py — тесты правки
                  конфигов; reports/ — измерения контрольной группы и сравнения с ней
docs/             спецификация с журналом деплоя, план переносимости
install*.sh       установщики, uninstall.sh — удаление
```

Правки — только в `runtime/` и `adapters/core-body.md`, затем `bash tools/build-digests.sh`,
`bash qa/lint.sh` и установщик: репозиторий — источник правды, живые копии всегда
собираются из него.
