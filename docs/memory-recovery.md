# Восстановление памяти Conductor

Сначала верните **целый приватный Git-репозиторий** в новую или пустую папку,
затем установите публичный runtime Conductor. Так сохраняются история и адрес
резервной копии, `backup-push.sh`, `.gitignore`, `.gitattributes`, уроки с их
архивами, `test-runs.log`, `reply-language` и все снимки `projects-memory/`.
Восстанавливаются файлы, попавшие в Git; незакоммиченные и игнорируемые файлы
источника clone не переносит. Скрипт резервирования берётся из самой копии.

Нужны Git, Python 3.12+ и Git Bash на Windows. Команды ниже запускаются из
публичного checkout Conductor. Примеры используют PowerShell; замените пути
и адрес приватного репозитория своими. Пароли и токены в адрес не вставляйте:
авторизуйте Git отдельно через его средство хранения учётных данных или SSH.

## 1. Полная копия памяти

```powershell
python tools/restore-memory.py clone --source 'D:/backups/conductor-memory.git' --destination 'C:/Users/YourName/.claude/conductor'
```

Источник может быть локальным обычным или bare-репозиторием (Git-хранилищем
без рабочей папки). Для удалённой копии явно укажите HTTPS или SSH:

```powershell
python tools/restore-memory.py clone --source 'git@github.com:YOUR_ACCOUNT/conductor-memory.git' --destination 'C:/Users/YourName/.claude/conductor'
```

Любая непустая папка назначения, даже с одинаковыми файлами, отклоняется.
Файл вместо папки, символическая ссылка и Windows junction тоже отклоняются.
Если runtime уже установлен, клонируйте память в другую новую папку и сначала
разберите содержимое существующей установки. Утилита не объединяет папки,
не удаляет их, не выполняет `reset` и не перезаписывает существующую память.
При ошибке возвращается код 1; оставшаяся частичная копия сохраняется для
осмотра. Следующий запуск направьте в другую новую папку.

Клонирование не запускает восстановленные скрипты, не переносит Git hooks
из шаблона и не включает внешние фильтры при извлечении файлов. Настройки
авторизации Git используются только для получения репозитория. После
восстановления проверьте `backup-push.sh`, `.gitattributes` и `origin` перед
любым ручным резервированием. Адрес `origin` остаётся адресом источника:
при восстановлении с локального диска он указывает на этот диск. Чтобы
возобновить отправку в удалённую копию, отдельно задайте проверенный адрес:

```powershell
git -C 'C:/Users/YourName/.claude/conductor' remote set-url origin 'git@github.com:YOUR_ACCOUNT/conductor-memory.git'
```

Существующий `backup-push.sh` отправляет ветку `main`. Проверьте, что именно
она восстановлена и отслеживает `origin/main`; для иного устройства копии
не включайте расписание до ручной проверки. На новой машине также нужны
настроенные Git `user.name` и `user.email` для будущих коммитов.

## 2. Runtime после памяти

Из проверенного публичного checkout Conductor:

```powershell
& 'C:/Program Files/Git/bin/bash.exe' ./install.sh --skip-companions
```

Сохраняйте предложенный установщиком язык из `reply-language`. Установщик
разворачивает runtime рядом с приватными файлами и подключает хуки Claude Code;
`.gitignore` приватной копии исключает runtime из следующих резервных копий.
Не запускайте установщик из восстановленного приватного репозитория.
При нестандартном содержимом `reply-language` используйте дополнительно
`--skip-global-md`: это сохраняет его байты, но пропускает установку глобального
`CLAUDE.md`. Установка правил для остальных сред остаётся отдельным шагом
публичного проекта.

Старая последовательность «установить runtime, скопировать несколько файлов,
сделать `git reset --soft`» неполна: она не возвращает `backup-push.sh` и
`.gitignore`. Изменение Git-истории само по себе файлы не восстанавливает.

## 3. Память конкретного проекта — только по выбору

Укажите имя каталога снимка и точную папку назначения. После переноса проекта
на другой диск его новое имя в `.claude/projects/` может отличаться от старого;
проверьте его самостоятельно. Автоматического сопоставления нет.

```powershell
python tools/restore-memory.py project --memory-repo 'C:/Users/YourName/.claude/conductor' --project 'OLD_PROJECT_KEY' --destination 'C:/Users/YourName/.claude/projects/NEW_PROJECT_KEY/memory'
```

Переносится только выбранный снимок, включая вложенные и скрытые файлы.
Папка назначения должна быть новой или пустой. Весь снимок проверяется до
копирования; ссылки и специальные файлы отклоняются. Файлы создаются без
разрешения замены. При ошибке ввода-вывода частичная новая папка остаётся для
осмотра, исходник сохраняется. Не меняйте обе папки параллельно с восстановлением.

## 4. Расписание Windows — отдельное явное действие

Сначала просмотрите описание задания, затем проверьте режим WhatIf:

```powershell
./tools/schedule-memory-backup.ps1 -MemoryDirectory 'C:/Users/YourName/.claude/conductor' -BashPath 'C:/Program Files/Git/bin/bash.exe' -DryRun
./tools/schedule-memory-backup.ps1 -MemoryDirectory 'C:/Users/YourName/.claude/conductor' -BashPath 'C:/Program Files/Git/bin/bash.exe' -WhatIf
```

Обе команды ничего не регистрируют и не запускают резервирование. Когда
скрипт и отправка в вашу копию проверены, отдельная команда включает расписание:

```powershell
./tools/schedule-memory-backup.ps1 -MemoryDirectory 'C:/Users/YourName/.claude/conductor' -BashPath 'C:/Program Files/Git/bin/bash.exe'
```

Создаётся `ConductorMemoryBackup`, ежедневно в 21:00 по местному времени
Windows; время меняется через `-DailyAt 'HH:mm'`. Задание работает от текущего
вошедшего пользователя, без прав администратора и сохранённого пароля.
Пользователь должен быть вошедшим в Windows; это не фоновая служба для
выключенной машины или сеанса после выхода. Пропущенный запуск разрешён при
следующей возможности; одновременные запуски задания запрещены.
Существующее задание не заменяется: осмотрите его отдельно или выберите другое
имя через `-TaskName`. Регистрация не запускает скрипт немедленно. Впоследствии
он выполняет свой обычный commit/push и пишет `backup.log` рядом с собой.

## Изолированная проверка

```powershell
python qa/memory-restore-test.py
```

Проверка создаёт временные локальные Git-репозитории и новый профиль. Сравнивает
байты всех тестовых артефактов, продолжение истории и отправку в локальный
bare-репозиторий, отказы при конфликтах и неудачном clone, перенос проекта,
реальную установку `install.sh --skip-companions`, описание расписания и передачу
пути тестового скрипта настоящему Bash. Тест расписания на других ОС пропускается.
Сетевое восстановление, реальное резервирование и регистрация живого задания
этим прогоном не проверяются. При ограничениях песочницы Bash тест установщика
должен выполняться с разрешённым доступом к его временной папке.
