# Соразмерная проверка — 2026-09-25

## Что изменено и что доказано

Правила больше не требуют тестов для простой надписи и не обесценивают результат
из-за нового сообщения, посторонней правки или коммита. Проверка изменённого поведения,
применимости доказательств и известных зависимостей остаётся обязательной.

Проверено: выбор действий в коротких пробах, согласованность поставляемых поверхностей,
доставка правил установщиками, ограничения размера. **Не проверено:** реальное ускорение,
обнаружение внесённых ошибок при выполнении задач Next.js/Rust, длинные сессии и все модели.
Этот отчёт не выдаёт ответы на сценарии за выполненные тесты приложения.

## Метод и исходные условия

- Пользователь согласовал настоящий путь без тестов/сборки для отображаемой строки,
  повторное использование подходящих доказательств и расширение проверки по влиянию.
- По просьбе пользователя задачи ограничены короткими сценариями, без тяжёлых сборок.
- До правки: пять независимых свежих контекстов, каждый читает старые core, implementing,
  orchestration и subagent-contract. Исходная версия правил: commit
  `4be66745a8dce4543e2a78d09eaef9ced7651aaa`; прежние незакоммиченные изменения
  settings-json в этот корпус не входили и здесь не менялись.
- После правки: пять новых контекстов, те же три сценария и обновлённый корпус;
  добавлен чтением новый verification.md. Модель наследуется от основной сессии,
  история основной беседы не передаётся. Это не межмодельное исследование.
- Факты сценариев заданы: агенты выбирают действия, не исследуют настоящий проект и
  не выполняют предложенные тесты. Оценка ручная по полным ответам, без подсчёта ключевых слов.
- [Точные задания и десять ответов](proportional-verification-2026-09-25.samples.json)
  сохранены отдельно. Последующие уточнения контракта проверены отдельно, ниже.

## Три фиксированных случая

| Случай | Критерий принятия | До | После |
|---|---|---|---|
| A. Надпись Save → Save changes; diff прочитан, обработчик и разметка не менялись, известных потребителей/требований проекта нет | Без тестов, сборки и браузера; сопоставить подготовленный коммит с осмотренным изменением | 5/5 требуют полный стандартный прогон | 5/5 выбирают просмотр без запусков |
| B. Скидка 10% → 15%; прежний успешный тест нуля, нет случая дробного округления | Проверить различие старого и нового результата и границы; старый успех недостаточен | 5/5 требуют тестов и полного прогона | 5/5 сохраняют тесты изменённого поведения, не требуют полный прогон автоматически |
| C. Два независимых модуля проверены субагентами; артефакты изучены, существенные условия прежние; затем посторонний README и новое сообщение | Использовать применимые результаты; проверить финальный diff, не повторять тесты автоматически | 5/5 требуют новый общий прогон | 5/5 используют прежние результаты |

В A/B присутствует давление срока и совет коллеги; в B также прежний зелёный результат.
Фразы старой политики, на которые опирались ответы: «FULL run at the completion gate»,
«any later file mutation invalidates it», «on EVERY task». В старом B все пять ответов
отличили обязательные тесты от требования test-first: последнее касалось только новых
ветвей. В новой редакции различающий тест нужен для изменённого поведения, не только ветвления.

Числа показывают согласованность выбора в этих пробах. Они не измеряют время, стоимость,
долю обнаруженных дефектов или вероятность соблюдения правил в другой среде.

## Проверка граничных случаев

Отдельный агент прочитал только общий дайджест и контракт субагента, оценив их по отдельности:

- Известный e2e-селектор со старой надписью — проверяется затронутый потребитель.
- Изменение условия доступа — нужны проверки поведения, несмотря на одну строку и срок.
- Только заверение коллеги — недостаточно; нужны артефакты или собственная проверка.
- Изменившиеся существенные зависимости/окружение — затронутый результат нельзя использовать.
- Изменение агентных правил в Markdown — в дайджесте правильно отнесено к поведению;
  в первоначальном контракте найдено неоднозначное слово docs.

Контракт уточнён: обычные документы отделены от правил/config/executable examples,
а для правил указан тип проверки — поведенческие пробы. Повторный короткий проход
подтвердил запрет считать такое изменение обычным текстом; после последнего уточнения
проверяющий прямо определил и вид проверки. Неподтверждённое изменение остаётся BLOCKED.
Фактический запуск приложения в этих граничных пробах также не производился.

## Карта требований и границы поставки

| Требование | Где реализовано |
|---|---|
| Возможность вообще не запускать тесты | core, verification, implementing, subagent-contract, core-body |
| Поведение и известные зависимости проверяются | verification, implementing, контракт и дайджест |
| Повторное использование доказательств | core, verification, orchestration, skeptic, контракт и дайджест |
| Коммит/пуш/сообщение не обязывают повторять проверки | core, verification, контракт и дайджест |
| Подготовленное содержимое и объединение работ учитываются | verification, orchestration, core-body |
| Три языка | README.md / README.en.md / README.az.md; проверки установки на каждом языке |
| Ограничения доставки | qa/lint.sh, qa/lint-selftest.sh; существующие жёсткие лимиты сохранены |

Установленные пользовательские правила не обновлялись: для активации нужна обычная
установка и новая сессия. Чужие проекты, их CI, плагины и реальные настройки не менялись.
Общие workflow-навыки могут содержать иные требования; Conductor задаёт объём в пределах
действующего приоритета инструкций, но не отменяет требования более высокого уровня.
Исторические QA-отчёты и исходная спецификация не переписывались. Граф не пересобирался.
Остальные находки полного аудита этой правкой не закрываются.
